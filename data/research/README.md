## 基线与可回滚历史

- 检索开始前基线：[834e348e17e47333777353e419dcc058f9f46846](https://github.com/MVChem/summer-research-2027/commit/834e348e17e47333777353e419dcc058f9f46846)

- `discoveredAt` 默认是本轮首次实际发现的 UTC 时间；写入后不改。少数记录的早期线索没有可恢复的精确时间，此时保留首次可精确认定的来源观察/核查记录时间，不重建更早时间；以 `discoveryTimestampNote` 明示，并在排序时间后标注 †。`verifiedAt` 是最后一次核对公开来源的 UTC 时间，可随复查更新；它是核查行为时间，不承诺每个链接均可全文读取。二者不是论文发表时间、招聘发布日期或提交时间

## 字段

格式 v2：`mentor_candidates.json` 是轻量索引，保留基线、评分规则、全部候选的稳定键/学校/时间/分数/方向，以及 `recordFile` 和 `detailPage`。完整资料位于 `batches/<批次>.json`；对应 Markdown 提供逐人来源与说明。排序页只展示概览，点击姓名即可进入详细记录。原有索引与排序 URL 保留。

每条完整候选包含：

| 字段 | 含义 |
|---|---|
| `id` | 稳定候选键，不使用原 1–200 编号 |
| `name`, `aliases`, `school`, `homepage`, `title` | 公开职业信息；别名用于去重 |
| `batch`, `discoveredAt`, `verifiedAt` | 检索批次与 ISO 8601 UTC 时间（结尾 Z） |
| `researchAreas`, `fitReason` | 方法/主题与相关理由；属于研究判断 |
| `physicalEvidence` | 真机证据状态、摘要和 `sourceIds`；历史或合作者平台不能证明当前本组设备 |
| `shortVisit` | 外校短期访问证据状态、摘要和 `sourceIds`；2027、约八周资格另行确认 |
| `scores`, `scoreReasons` | 四项分数与逐项依据；未知的短期机会证据计 0 |
| `sources` | 来源 `id`, `label`, `url`, `summary`, `verifiedAt`；可选 `publishedAt` 必须有明确页面日期依据 |
| `unknowns` | 仍未确认的任职、招募、访问资格、时长、经费、设备或指导条件 |

证据优先来自学校、本人、实验室与原始项目/论文。只存简短原创摘要和链接，不复制完整网页。未读取或读取失败的页面不当成已成功阅读全文的来源。只有第一方页面的可核对索引摘录时，必须在来源摘要和可选 `retrieval` 字段注明 indexed-only，并保留实时重查限制；不能据此宣布确定名额或资格。无法重现的招募文本不计入机会证据。信息冲突时明确保留不确定性。

## 排序规则 v1

这是**继续筛选的研究优先级**，不是录取概率、成功率或导师接收承诺。总分 100：

| 项目 | 上限 | 评分含义 |
|---|---:|---|
| `fit` | 40 | AI 与机器人方法直接匹配程度；35–40 直接机器人学习/具身 AI，25–34 强相关学习控制/感知/HRI，15–24 可迁移或系统侧，0–14 较弱或未核实 |
| `physical` | 25 | 21–25 明确近期实体机器人实验；13–20 公开但较旧/合作/间接线索；1–12 弱线索；未知或只有仿真 0 |
| `shortVisit` | 20 | 15–20 有来源支持相容访问时长、时期与资格（20 需明确 2027 约八周）；5–10 当前明确但未说明时长的外校访客/实习询问路径；仅历史来访先例、未知、只有 PhD/本校/长期岗位或不相容条件 0 |
| `freshness` | 15 | 11–15 有明确 2026 年相关研究/任职/招募证据；6–10 有 2025 年证据；1–5 较旧或无日期但可读取的相关来源；未核实 0 |

每项必须有具体理由；不得把“今天打开网页”当成研究或岗位在 2026 年更新。网页显示未来活动日期不证明活动已完成。新 AP 信息需任职来源支持，不单独加分。未知短期机会不会因研究匹配强而变成确认机会。总分相同时按 `fit`、`physical` 降序，再按最早发现时间、姓名排序。

不依据推测的族裔、性别、国籍、照片或姓名排序。只记录公开职业研究事实；不提交使用者私人资料、浏览器备注、联系状态或邮件内容。本检索没有联系导师或发送邮件。

## 复核与生成

在仓库根目录执行（Python 3.10+，仅标准库）：

```sh
python scripts/research_ledger.py --write
python scripts/research_ledger.py --check
python scripts/test_research_ledger.py
```

`--write` 从批次 JSON 生成轻量索引、排序表和各批详细 Markdown。新增候选先加入新批次 JSON；修正已有记录只修改受影响的批次，保留稳定键和首次时间，并用独立 commit 记录。分片文件经过 Git 版本管理，不复制替代历史。

校验原 200 位的语义内容与基线一致、姓名/别名/主页去重、UTC 时间、分数范围和证据链接引用，并检查排序文件与 JSON 一致。不会修改原数据或应用。自动校验不能替代网页事实核验；每批仍需人工复核当前任职、真机与访问条件。

提交时记录对应来源与核查时间，重新读取最新 main 后建立单父提交；分支只允许 fast-forward 更新。修正已发布候选时保留其 `id` 和首次 `discoveredAt`，更新证据与 `verifiedAt` 并单独提交。

## 任职类别

主名单包含官方大学目录明确列为 faculty 的研究人员，保留准确的 Research Professor、Systems Scientist 等任职标签，不将这些职称改写成 Assistant/Associate/Full Professor。大学 faculty 分类、研究指导经历与具体访客接收权限是不同事项；后者仍需另行确认。独立研究机构、未核实大学 faculty 任命的线索另列，不混排。

### 后续读取失败与链接校验

可选 `verificationAttempts` 单独记录后续读取尝试的 UTC `attemptedAt`、`sourceIds` 与 `outcome`。失败尝试不重写首次发现时间，也不冒充成功来源核查；具体限制同时列于详情的未确认事项。校验器检查尝试的时间和来源引用，并验证详情页到机构说明的显式锚点，避免规则链接失效。

### 姓名变体的人工复核

精确姓名/已知别名和主页重复继续触发校验失败。额外的首名与末名匹配（包括省略中间首字母）产生人工复核警告，而不自动合并记录。复核须结合机构、官方主页和公开任职信息；仅同姓不视为同一人。明确确认的别名补到已有记录，保持首次发现时间不变。

### 现场访问与远程研究线索

本排序优先考虑约八周的现场研究访问。仅远程 internship 的明确邀请仍保留为有用的次级线索，并在状态中突出显示，但不增加现场短访证据分。可选 `remoteInquiryEvidence` 保存该公开远程入口的摘要、来源和核查时间；它不代表现场接收、资助或 2027 名额。

### 真机证据受限的机器人 AI 备选

强机器人 AI 方法、值得继续核实的外校研究访问线索可以作为备选，但不能与已核实的 AI＋实体机器人证据混称。仅仿真或未核实机器人部署的物理分为 0；弱或较旧的线索按实际证据给低分。不能仅用一般 AI 标签扩充名单，也不能因访问询问路径而增加物理分。

轻量索引在受限记录上保留 `physicalEvidenceStatus` 与 `physicalEvidenceLabel`，排序姓名列显式标记“仅仿真；真机待核实”“真机待核实”或“弱/历史真机线索”。机器人采集的数据与在线学习部署也分别注明。标签不改变已核实记录的分数或发现时间，具体场地、设备和访问权限仍见逐人证据。
